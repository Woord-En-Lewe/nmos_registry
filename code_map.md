# Code Map for NMOS Registry

## Summary
The NMOS Registry implements the AMWA IS-04 specification for discovery and registration of networked media resources. It follows the Module-Infrastructure-Module (MIM) architecture, separating business logic from technical implementations.

## Architecture
- **Business Module (BM)**: `internal/registry` (future logic for resource management)
- **Infrastructure Module (IM)**: `internal/infrastructure`
  - **Persistence**: `internal/infrastructure/persistence` using SQLite (in-memory) and `sqlc` for type-safe queries. Uses `modernc.org/sqlite` (pure Go driver).
  - **Transport**: `internal/infrastructure/transport/http` using `go-chi/chi` for routing NMOS APIs.

## When to Use
Use this project as a centralized NMOS IS-04 Registration and Query service for media networks.

## Public Types
### `internal/registry`
- `Node`, `Device`, `Source`, `Flow`, `Sender`, `Receiver`: Business module representations of IS-04 NMOS resources.
- `IRepository`: Interface for resource persistence (CRUD operations and health monitoring).
- `INotifier`: Interface for real-time updates (Query API notifications).
- `ResourceManager`: Core logic for managing NMOS resource lifecycles (registration, updates, deletion).
- `HeartbeatEngine`: Manages Node health timestamps and background garbage collection for expired resources.
- `ResourceType`: Enum for NMOS resource categories (node, device, source, flow, sender, receiver).

### `internal/infrastructure/persistence/db` (Generated by sqlc)
- `Nodes`: Represents an IS-04 Node resource in the database.
- `Devices`: Represents an IS-04 Device resource.
- `Sources`: Represents an IS-04 Source resource.
- `Flows`: Represents an IS-04 Flow resource.
- `Senders`: Represents an IS-04 Sender resource.
- `Receivers`: Represents an IS-04 Receiver resource.
- `Subscriptions`: Represents a Query API subscription.
- All resource types use `json.RawMessage` for complex NMOS fields (tags, api, caps, etc.) to ensure type safety and flexibility.

## Public Functions
### `internal/registry`
- `NewResourceManager(repo IRepository) *ResourceManager`: Creates a new instance of the ResourceManager.
- `NewHeartbeatEngine(repo IRepository, expiryDuration time.Duration, cleanupInterval time.Duration) *HeartbeatEngine`: Creates a new HeartbeatEngine.
- `HeartbeatEngine.Heartbeat(ctx context.Context, nodeID string) error`: Updates the health timestamp for a Node.
- `HeartbeatEngine.StartGarbageCollector(ctx context.Context)`: Runs a background loop to prune expired resources.
- `HeartbeatEngine.PerformCleanup(ctx context.Context)`: Manually triggers a cleanup of expired Nodes.

### `internal/infrastructure/persistence`
- `SQLiteRepository`: Implementation of `registry.IRepository` using SQLite and sqlc.
- `NewSQLiteRepository(db *sql.DB) *SQLiteRepository`: Creates a new instance of the SQLiteRepository.
- `InitDB(db *sql.DB) error`: Initializes the database schema using the embedded `schema.sql`.

### `cmd/server`
- `main()`: Entry point for the NMOS Registry server. Initializes DB and starts the HTTP server.
